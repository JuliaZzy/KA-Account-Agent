先分清两件事
完整月报原来根本没生成完（每 Run 只许 2 次调用），所以早期「报表 15–60 秒、¥0.02」不是月报。 后面 C 刀是在「真的写完六节 + 审阅」上砍墙钟；空月饼图和聊天第一句是质量，不并进 C 对比。

怎么评估、怎么选

硬约束

价格、SKU、MOQ 仍由代码算。月报这条线上，模型只负责规划问题、写正文和审阅；绑哪张图、空结果画不画、点名月份有没有数，都改成代码判定。

先量再改。C 之前补记漏掉的四节正文（约 ¥0.016–0.021），否则「合并调用」会看起来像假降。一次一两刀，单测 → 冒烟 → 再混跑。

平衡口径

墙钟看混跑中位和轻任务排队，不拿单次失败重试当刀无效。质量题（假饼、开口）单独冒烟，不写进 C 的秒数差。

生产默认不抬：Worker=5、GATE_USER=5、GATE_ORG=10。要打满组织闸门就改提供负载，不把上限改成 30/50。月报本身就长，审阅可以更慢换更便宜。

C 各刀：选项、取舍、怎么判

用户原方案是 0–8 顺序落地。每刀的判据是：并发 1 能否看见重叠或少调用，混跑里轻任务是否少排，账本 purpose 是否对得上。

先能测完整月报 前提，不是优化

选项 A：继续用残缺月报数字做 C。选项 B：把 report 路由从 2 次 / 4000 token 放到 24 次 / 24000，并补记漏掉的四节正文。

选 B。不放宽就没有洞察和审阅；不补账，后面「合并四节洞察」会把本来没入账的钱算成省下来的。代价立刻可见：单份约 ¥0.21、127–180 秒，客户端超时要从 180 提到 300。

闸门：测到上限，但不改生产默认

Worker=5 且只有一个用户时，父 Run 等待子任务已经放掉座位，同时最多 5 个子 Run。Redis 里组织/用户/全局峰值都是 5，GATE_ORG=10 打不满。有人提议把 GATE_USER/ORG 改成 30/50 再加 worker——否决：那测的不是生产上限。

选法：闸门保持 5/10/32；worker 临时 12，客户端 18，联采三个用户轮转。组织峰值到 10，吞吐 10.4→15.2 次/分，月报中位 152→128 s，轻任务最长 130→48 s。短单排队中位 6→16 s，因为客户端 18 大于组织 10，是预期。跑完 worker 收回 5。

进程内并行加的是模型闸门
同一 worker 里图表和四节正文同时打模型，GATE_MODEL 从 5 到 10，组织计数不变。不同 worker 领不同 Run 才能抬 GATE_ORG。

诚实闸：和 C 分开做

产品意图：用户点名 10 月，聊天要说 10 月没数据；右侧月报仍可写近半年趋势。不把整份报告短路成「没有数据，结束」。

出图

规划只写问题。代码打 pie_category / trend / bar，一组结果最多一张图。

空结果或维度对不上：跳过模型，不走 code.fix。画出来对不上绑定行的丢掉。

审阅放宽成：有数据才必须引用图。不要让模型回声 source_dataset。

记录 32：rpt-07 不再出现 Cerise 那种带值品类/产品饼；rpt-01 仍有 Chocolate / Biscuits / Grocery。

聊天开口

只改提示不够。ANSWER 常先说「月报已生成」，评分器看的是聊天全文是否带「没有数据」。

指标合计里没有该 YYYY-MM 就打 named_period_empty；模型没按这句话开口，代码把「{期间}没有数据」接到最前。

ROUND(SUM(float8), 2) 在 Postgres 不存在，m2 一失败标记就打不上，顺手改成 CAST AS numeric。

记录 34：rpt-07 第一句「2026年10月没有数据」；rpt-01 有数，仍说月报已生成。

最后落在产品上的状态

比这条对话开始时好在哪

月报真的写完：六节、洞察、审阅都在，不再把 COST_BUDGET_EXCEEDED 说给用户。

Worker=5 混跑：月报中位大约少三分之一（225→152 s），吞吐 8.1→10.4 次/分，同组成本约低 26%。

单份并发 1 的 rpt-01 在 C 刀 5–8 后到过 88.5 s（当时还是 DeepSeek 审阅）。

空月不再用别的月份或产品饼交差；聊天第一句由代码钉死。

审阅更便宜；账本能按 write / review / optional 分开看。

故意没动、或还没再量

默认 Worker 仍是 5。W=12 只证明 GATE_ORG=10 打得满，不是新默认。

q* / s* 交错改了派发顺序，混跑有没有真的同时开工还没重测。

Qwen 审阅把单份墙钟抬回去一截（rpt-01 约 3–4 分钟），这是接受过的交换。

全量 golden、混跑 C 对比，没有在开口/Qwen 之后重跑，避免把质量刀写进耗时差。

一句话
先让月报完整可测，再用代码能定的事（并行、模板 SQL、空月跳图、开口）换墙钟和诚实；模型只留写作和审阅，审阅还可以更慢更便宜。生产并发默认不变。
