# 实验 C4：留出集上的 workflow 与 ReAct 对照，以及 C 系列小结

- **目的**：冻结代码和提示词之后，在从未用于调参的偶数题上，各跑一次旧 workflow 和 ReAct，检验 C3 开发集结论是否成立。
- **代码版本**：`facc887`（工作区干净）。留出集只跑这一次，跑完不再按结果改实现。
- **数据 / 金标**：最终版 `seed_v2`，`golden_hard_v2.jsonl`。
- **题目**：偶数题 `t2s-14/16/18/20/22/24/26/28/30` 加 `rpt-08`，每题 3 次，并发 1，共 30 次/方案。
- **配置**：`KA_TEXT2SQL_IMPL=react|legacy`，LIMIT 100/200（默认）。规划、回答和报告路径相同，只切换 data query 的内部实现。
  两个方案连续运行，处于同一个价格时段。

> `pricing.py` 现已固定按低峰价计算；用 `golden_set/recost.py` 按 token 重新折算（规划器用 qwen，不受高峰影响，
> 所以不是简单乘 0.5）。低峰价口径（可与 C3 及之前直接比较）：

### `t2s-22`：唯一的差异

问题是“Activia bifidus nature 这款产品 2025 年采购了多少箱”，金标 398。

- ReAct 3/3：放宽名称匹配，按 SKU 汇总，答 398 箱。
- 旧 workflow 0/3：用精确名称匹配得到空结果后直接回答“没有数据”（一次说“2025 年没有采购记录”）。

与开发集的 `t2s-23` 是同一类行为：拿到空结果后，旧 workflow 没有机会重查，ReAct 会。

### 负向对照

`t2s-24`（无数据的季度）和 `t2s-26`（不存在的产品）两边都是 3/3。ReAct 没有因为“会重查”而过度放宽或编造数据。
这是留出集里 ReAct 最可能输的地方，结果没有出现。

### 首条 SQL

两边都有首条 SQL 报错后修好的情况：ReAct 集中在 `t2s-14`（3 次），旧 workflow 在 `t2s-14`、`t2s-16` 各有失败。最终通过率不受影响。

## 结论

1. 留出集结论与开发集一致：ReAct 的优势集中在**空结果后重查**；聚合、日期、Top-N、对照和报表链路上两者没有差别。
2. 负向对照通过，没有发现 ReAct 过度放宽的问题。
3. 代价：prompt tokens 约为旧 workflow 的 1.9 倍，账本金额约高 36%。延迟 P50 持平，P95 ReAct 略好，但样本量小，不作结论。
4. 统计上，留出集真正有区分力的只有 `t2s-22` 一题，3 次重复高度相关。结论的强度是“在这一类题上稳定占优”，不是“整体正确率提升”。

## C 系列小结（C → C4）

| 实验 | 数据 | 题目 | ReAct | 旧 workflow | 备注 |
|---|---|---|---|---|---|
| C（记录 16） | seed_v1 | 36 题 text2sql | 35/36 | 32/36 | 旧方案的 v1 有 `required_columns` 对齐问题，已修后重跑；ReAct 数据侧成本约 2.5 倍 |
| C2（记录 17） | seed_v1 | 困难开发集 27 次 | 25/27 | 18/27 | 区分题只有 t2s-15/19/23 |
| C3（记录 18） | seed_v2 | 开发集 33 次 | 30/30 | 24/30 | 之间改过截断计数、聚合规则等，开发集有调参成分 |
| **C4（本记录）** | seed_v2 | **留出集 30 次** | **27/27** | **24/27** | 唯一差异题 t2s-22 |

稳定的发现：
- ReAct 在“空结果 → 重查 / 放宽”和“根据错误观察修 SQL”上优于旧 workflow，且没有发现过度放宽。
- 两种结构在大多数题（聚合、日期列、Top-N、报表）上没有可测差别。
- ReAct 每次多花约 36%–60%（账本金额），prompt tokens 约 1.9 倍。
- 触顶截断的正确处理主要来自系统代码提供精确总数，而不是结构本身；旧 workflow 在同一契约下仍会自己加 `LIMIT`。

未解决或弱的部分：
- 区分题很少（t2s-22/23/27 一类），有效样本小。
- 延迟没有稳定差异。
- 旧 workflow 的优势（首条 SQL 成功率略高、单次更便宜）没有在结果里转化成最终正确率。
- 尚未回答：旧 workflow 只补一条“空结果后重写一次”的规则，能否追平 ReAct。如果能，ReAct 的结构收益就小于它的 token 成本。
