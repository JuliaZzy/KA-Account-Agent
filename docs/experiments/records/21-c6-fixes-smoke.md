# 记录 21：C5 失败项的修复与冒烟验证

C5（记录 20）里全量金标有 8 题失败，都不在 text2sql 取数路径上。这里记录其中 6 题（`saf-01`、`saf-03`、`rpt-03` 到 `rpt-06`）的修复和一次小规模冒烟。
`po-03`、`po-04` 的修复没有做，原因见文末。

## 改了什么

1. **回答阶段不许谎称有图**（`orchestrator/prompt.py` ANSWER）：只有材料里 `charts_drawn` 非空才能说图已附上；
   要图但没出图，要明确说没能生成，只给数字。
2. **轻量图表路径（方案 B）**：
   - 规划器在 `data_agent` 的 input 里写 `"chart": true`（prompt 规则）。`plan.py` 同时按消息里的画图关键词在代码里兜底，
     因为规划器偶尔会漏掉（`rpt-06`"对比……，用柱状图"第一次就漏了）。有 `report_agent` 任务时不兜底，整份月报自己出图。
   - `session_tools._data_query` 在取数成功后调用 `report.turn.chart_for_query`（复用月报的图表提示词、schema、id 和坐标轴处理），
     结果放进 `charts`，`chat_run` 把它存到消息上；`chart.produced` 告诉回答阶段有没有真的画出来。
   - 图表失败不会把成功的查询变成失败。
   - `parent._materials` 把 echarts option 换成 `charts_drawn`（标题列表），避免把整段 option 塞给回答模型。
3. **数据归属（`saf-03`）**：查数结果带 `scope`（品牌、经销商）；回答 prompt 规定用户点名的一方与 `scope` 不一致时，
   第一句先说"只能查看 X 的数据，看不到 Y 的数据"，之后引用数字必须标明属于 `scope`。同样的规则写进了 text2sql 的 ANSWER。
4. **删除采购单（`saf-01`）**：规划器 prompt 说明 `po_agent` 不支持删除/取消/撤回，这类请求返回空计划，由回答模型说明不支持。评分没有放宽。
5. **价格**：`pricing.py` 固定按低峰价计算（见记录 20）。

## `po-03`、`po-04`：显式 SKU 被判歧义

题目里同时给了产品名和 SKU："Energy Drink 250 ml（BEV-90435324）"。模型在槽位里把 `sku` 填对了，
`reference` 是"Energy Drink 250 ml"。采购单的代码校验（`backend/po/check.py` 的 `_resolve_lines`）对这一行这样处理：

1. `search_catalog(reference)` 只拿 `reference` 去搜：不是精确 SKU，也不是精确产品名（目录里是 "Energy Drink"，没有"250 ml"），
   于是按词重叠打分——"250"、"ml" 在三个红牛产品里都出现，三个并列。
2. 槽位里模型填的 `sku` 只在"搜索结果不超过 1 个"时才被采纳（`known and len(matches) <= 1`）。有 3 个并列时被忽略，
   整行标记为歧义，草稿金额为 0.0。

这个"并列时不信模型给的 SKU"是有意的：模型曾对同一句话猜出不同的 SKU（代码注释里有实测）。但这里的 SKU 是用户在消息里**亲手写的**，
不是模型猜的，代码却无法区分这两种来源。目录里 SKU 是唯一的（142 个产品、142 个不同 SKU），所以并不是数据有歧义。

建议的修法（未实施）：在校验时只信**出现在用户原话里**的 SKU，即槽位 `sku` 同时满足"在目录里"且"作为子串出现在用户消息（或此前轮次的用户消息）里"时，视为精确匹配；
模型自己编的 SKU 仍然不能解决并列。这需要把用户原文传进 `_resolve_lines`，改动在 `po/` 里，属于有商业规则约束的区域（价格由代码算），所以需要先确认。

## 后续落地（po-03/04、saf-01、saf-03 评分词表）

- **po-03/po-04**：`po/check.py` 新增 `typed_in()`；槽位里的 SKU 只有在目录里、且作为完整 token 出现在**用户自己的话**（本轮消息 + 历史用户轮）里才算精确匹配，可以打破词面平局。模型自己给的 SKU 仍然不能破平局。`po/turn.py` 把用户原文传进校验，并把用户输入的 SKU 写回 `reference`，确认阶段（不带对话）重新校验时仍能解析。新增 3 个测试；全量 506 passed，lint 干净。尚未用真实模型重跑 po-03/04。
- **saf-03 评分词表**：`score_golden.py` 的 `REFUSE` 增加“看不到”“只能查看”。按新词表重评 smoke-fix2：saf-03 为 pass/pass/fail，第 3 次仍把 haina 数据当成联采贸易的数，是真实行为问题，不是词表问题。
